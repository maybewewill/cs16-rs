# Checklist: the game of cs-game with the original client (phase 2C)

Manual checks of the game logic of `cs-server --proto48` (team and class menus, rounds, money, scoreboard, chat, radio, observer, buying armor, status bar, radar, night vision, map change) with the original client (Steam CS 1.6, protocol 48). The automated tests run against `cs-probe` only and compare with the ReGameDLL_CS source; this checklist is the comparison with the real client. 👤 These checks are run by the project owner. The game is ported from ReGameDLL_CS (vanilla `mp.dll` behaviour). In the Expected column a value that the ReGameDLL_CS source states names the file it comes from (master, read 2026-11-22); every other value is marked "from memory - confirm": it is what the original game is remembered to show, not something checked, so a difference is a result to write down, not necessarily a bug. No line below is a pass until the owner has filled it in.

Start the server from the repository root:

```
cargo run -p cs-server -- --proto48 --map de_dust2 --port 27015
```

(Set `CS16_GAMEDIR` to the game folder if the server does not find the game: `set CS16_GAMEDIR=D:\SteamLibrary\steamapps\common\Half-Life` in `cmd`.) The server console takes `status`, `sv_restartround 1`, `changelevel de_dust2` and `quit`.

In the original client, open the developer console (`~`) and type:

```
connect 127.0.0.1:27015
```

Rows 4 to 9, 13 and 14 need a second player: a second copy of the original client on the same machine or another one (use the same `connect`, with its own name), or the stand-in `cargo run -p cs-probe -- --connect 127.0.0.1:27015 --seconds 600 --cmd "jointeam 2" --cmd "joinclass 1"` (a probe that joins the counter-terrorists and stands still; it does not see or say anything). The first player is a terrorist unless a row says otherwise. Rows 7, 8, 13 and 14 need a TEAMMATE of the owner, so the probe must join the owner's team: when the owner is a terrorist start the probe with `--cmd "jointeam 1" --cmd "joinclass 1"` instead (`jointeam 1` is the terrorists, `jointeam 2` the counter-terrorists), or use a second real client on the owner's team. Rows 4, 5, 6 and 9 need an enemy, so the probe in the command above (`jointeam 2`) fits them. For a quick round without waiting, `mp_freezetime 3`, `mp_roundtime 1` and `sv_restartround 1` can be typed in the server console.

Fill in the date and the result (pass / fail plus what was seen) of every line. When a line fails, write down what the client showed and what the server window printed.

What is not checked here because it does not exist yet (registry: `game_weapons_and_equipment_items`, `game_objectives`, `game_hint_messages` in `docs/parity/entities.toml`): weapons, grenades and buying them (a weapon purchase says it cannot be bought), the bomb, hostages, the VIP and escape (a round never ends by time on a map with an objective, and the buy menu has no defuser), the hint messages (yellow tips), the original `pm_shared` movement (a different server movement can show as small corrections; the movement port is a separate plan), and observer sound and visibility from the followed player's spot.
